## 一、引言

### 1.1 项目背景

随着线上点餐需求的增长，餐饮商家需要一套配套的后台管理系统维护菜品、套餐与订单，同时为顾客提供浏览菜品、加入购物车、下单的用户端。本项目模拟真实企业开发场景，综合运用 Java、Spring Boot、MyBatis 等技术完成一个可运行的外卖管理系统。

### 1.2 项目目的

- 掌握 Spring Boot 自动配置、Spring MVC 请求处理流程、MyBatis ORM 与动态 SQL；
- 实践「实体 — Mapper — Service — Controller」分层开发与前后端分离调用；
- 完成需求分析、数据库设计、编码实现、功能测试的完整开发闭环。

### 1.3 系统范围

系统分为两端：

- **后台管理端**：面向门店员工，负责分类、菜品、套餐、订单、员工等基础数据与业务处理。
- **用户端**：面向顾客，负责验证码登录、菜品浏览、购物车、地址管理与下单。

## 二、需求分析

### 2.1 功能性需求

#### 2.1.1 后台管理端

| 模块 | 功能需求 |
| --- | --- |
| 登录管理 | 员工输入用户名、密码登录；登录成功进入后台并拥有操作权限；退出后清除登录状态，返回登录页。 |
| 分类管理 | 分类的新增、查询、修改、删除；分类区分菜品分类与套餐分类；分类下存在菜品或套餐时禁止删除。 |
| 菜品管理 | 菜品新增、查询、修改、启售/停售、删除；菜品关联所属分类；被套餐引用的菜品禁止删除。 |
| 套餐管理 | 套餐新增、查询、修改、启售/停售、删除；套餐可包含多个菜品及份数；启售状态下禁止删除。 |
| 订单管理 | 按订单号、状态查询订单；查看订单明细；修改订单状态。 |
| 员工管理 | 员工列表、新增、修改、启用/禁用。 |

#### 2.1.2 用户端

| 模块 | 功能需求 |
| --- | --- |
| 用户登录 | 获取短信验证码；凭手机号 + 验证码登录，新手机号自动注册；退出登录。 |
| 菜品展示 | 登录后进入首页，展示全部分类；选中分类后展示该分类下的启售菜品。 |
| 地址管理 | 地址列表查询、新增地址、设置默认地址、编辑地址、删除地址。 |
| 购物车 | 添加商品到购物车、查询购物车、修改商品数量、移除商品。 |
| 下单 | 选择收货地址、填写备注，提交结算后由购物车生成订单及订单明细，并清空购物车。 |

### 2.2 非功能性需求

- **可用性**：页面操作反馈明确，业务错误以提示信息返回，不出现服务器错误白页。
- **安全性**：未登录用户不能访问业务接口；后台与前台会话相互独立。
- **可维护性**：分层清晰，实体、接口、实现、页面分离，便于扩展。
- **兼容性**：支持主流浏览器访问。

## 三、系统架构设计

### 3.1 分层架构

系统采用经典的 MVC + 三层架构，自上而下：

```
┌─────────────────────────────────────────────┐
│  表现层（前端）                                │
│  static/admin（后台页面）  static/user（用户端）│
├─────────────────────────────────────────────┤
│  Controller 层（Spring MVC）                  │
│  admin 包：员工/分类/菜品/套餐/订单            │
│  user  包：用户/地址/购物车/订单/首页          │
├─────────────────────────────────────────────┤
│  Service 层（业务逻辑）                        │
│  service 接口 + service.impl 实现             │
├─────────────────────────────────────────────┤
│  Mapper 层（MyBatis）                         │
│  mapper 接口 + resources/mapper XML           │
├─────────────────────────────────────────────┤
│  数据层  MySQL：takeout_db                     │
└─────────────────────────────────────────────┘
```

### 3.2 关键组件

| 组件 | 作用 |
| --- | --- |
| `R<T>` | 统一响应结构（code、msg、data），前端按 code 判断成功失败。 |
| `Constants` | 会话键、启用/停售、订单状态等常量统一定义。 |
| `BaseContext` | 基于 ThreadLocal 在请求线程内传递当前登录用户 ID。 |
| `LoginCheckInterceptor` | 登录校验拦截器，区分后台 `/employee/**` 与前台 `/user/**`。 |
| `WebMvcConfig` | 注册拦截器，放行登录、验证码等公开接口。 |
| `GlobalExceptionHandler` | 全局异常处理，业务异常统一封装为 `R.error`。 |

### 3.3 技术选型说明

- **Spring Boot**：简化项目搭建与自动配置，内嵌 Tomcat，无需单独部署 Web 容器。
- **Spring MVC**：提供 `@RestController`、`@RequestMapping`、参数绑定与 JSON 响应。
- **MyBatis**：通过 Mapper 接口与 XML 完成 SQL 映射，支持动态 SQL 与批量操作。
- **MySQL**：存储员工、分类、菜品、套餐、用户、地址、购物车、订单等数据。

### 4.2 实体关系

- 一个 **分类** 下包含多个 **菜品**；菜品 `category_id` 关联分类 `id`。
- 一个 **分类** 下包含多个 **套餐**；套餐 `category_id` 关联分类 `id`。
- 一个 **套餐** 包含多个 **菜品**，通过 `setmeal_dish` 关系表关联。
- 一个 **用户** 拥有多个 **地址**、多个 **购物车项**、多个 **订单**。
- 一个 **订单** 包含多个 **订单明细**；明细记录商品、数量、单价。

## 五、核心业务流程

### 5.1 员工登录流程

1. 员工在登录页提交用户名、密码；
2. `EmployeeController.login` 调用 `EmployeeService.login`；
3. Service 通过 `EmployeeMapper.getByUsername` 查询员工，校验密码与启用状态；
4. 校验通过，将员工 ID 写入 Session；拦截器后续请求据此判断登录状态；
5. 退出时移除 Session 属性，返回登录页。

### 5.2 用户验证码登录流程

1. 用户输入手机号，点击获取验证码；后端生成 6 位验证码写入 Session（实践项目模拟短信下发）；
2. 用户提交手机号与验证码；Service 比对 Session 验证码；
3. 校验通过：用户存在则直接登录，不存在则自动注册；用户 ID 写入 Session，验证码销毁。

### 5.3 下单流程

1. 用户在购物车确认商品，选择收货地址并填写备注，提交结算；
2. `OrdersService.submit` 查询当前用户购物车；购物车为空则提示无法下单；
3. 汇总购物车商品总金额，校验收货地址；
4. 生成订单号，组装订单主体并写入 `orders`；
5. 将购物车逐条转为订单明细，批量写入 `order_detail`；
6. 清空该用户购物车，返回订单及明细。

### 5.4 分类删除校验流程

删除分类前，分别统计该分类下的菜品数与套餐数；只要存在关联数据，即提示不能删除，保证数据完整性。

## 六、接口设计

### 6.1 统一响应结构

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

- `code = 1`：成功；`code = 0`：失败；失败时 `msg` 为提示信息，`NOTLOGIN` 表示未登录。
- 接口采用 RESTful 风格：GET 查询、POST 新增、PUT 修改、DELETE 删除。

## 七、关键技术与难点

1. **IOC 与依赖注入**：Controller、Service、Mapper 均交由 Spring 容器管理，通过 `@Autowired` 注入，降低组件间耦合。
2. **AOP 思想的应用**：登录校验、异常处理以横切方式实现，业务代码无需重复编写鉴权与异常捕获。
3. **ORM 映射**：XML `<resultMap>` 建立表字段与实体属性映射，下划线命名自动转驼峰。
4. **动态 SQL**：列表查询使用 `<where>` + `<if>` 拼接条件；套餐菜品、订单明细使用 `<foreach>` 批量插入。
5. **事务控制**：套餐保存/修改、下单等涉及多表写入的操作，使用 `@Transactional` 保证数据一致性。
6. **会话与线程上下文**：拦截器将登录用户 ID 存入 Session，并同步到 `BaseContext`，业务层直接获取当前用户。

## 九、总结

本系统按照需求完成了后台管理与用户端共 10 个功能模块，实现了从数据库设计、后端分层编码到前端页面调用的完整流程。开发过程中实践了 Spring Boot、Spring MVC、MyBatis 的核心用法，加深了对 IOC、AOP、ORM、自动配置与动态 SQL 的理解。后续可扩展图片上传、真实短信与支付接入、订单超时处理、数据统计报表等功能。
